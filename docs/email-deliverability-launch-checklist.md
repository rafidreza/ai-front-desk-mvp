# Email Deliverability Launch Checklist

This checklist is for the person who controls `daemion.io` in Cloudflare and the Postmark account.
It explains the non-code work needed before Daemion sends real login codes or digest emails from the domain.

## Goal

Make emails from `support@daemion.io` look legitimate to inbox providers.

Without these records, Gmail and Outlook may treat Daemion emails as spam or may reject them.

## Accounts Needed

- Cloudflare access for `daemion.io`.
- Postmark access for the production server.
- A sending address decision, currently expected to be `support@daemion.io`.

## Step 1: Add the Domain in Postmark

In Postmark, add `daemion.io` as a sender domain.

Postmark will show DNS records that need to be copied into Cloudflare. The exact DKIM value is generated by Postmark, so do not invent it manually.

## Step 2: Add DNS Records in Cloudflare

In Cloudflare, open `daemion.io` and add the records Postmark gives you.

Typical records look like this:

| Type | Name | Value | Why it matters |
|---|---|---|---|
| TXT | `daemion.io` | `v=spf1 include:spf.mtasv.net ~all` | Allows Postmark to send email for the domain. |
| TXT | Postmark DKIM host | Postmark DKIM value | Proves Postmark is allowed to sign Daemion emails. |
| CNAME | Postmark return-path host | Postmark return-path target | Improves bounce tracking and sender reputation. |
| TXT | `_dmarc.daemion.io` | `v=DMARC1; p=none; rua=mailto:dmarc@daemion.io; adkim=s; aspf=s` | Starts monitoring whether emails pass SPF/DKIM. |

Example:

If Postmark says the DKIM host is `20260531pm._domainkey.daemion.io`, add that exact host in Cloudflare. If Postmark gives a different host, use Postmark's value.

## Step 3: Verify in Postmark

After saving the DNS records, go back to Postmark and click verify.

DNS can take minutes or sometimes a few hours to update. If verification fails immediately, wait and try again before changing the record.

## Step 4: Set Production Email Secrets

For the API Worker, set:

```bash
cd apps/hono-api
npx wrangler secret put EMAIL_FROM_ADDRESS --env staging
npx wrangler secret put POSTMARK_SERVER_TOKEN --env staging
npx wrangler secret put POSTMARK_MESSAGE_STREAM --env staging
```

Recommended values:

- `EMAIL_FROM_ADDRESS`: `Daemion <support@daemion.io>`
- `POSTMARK_MESSAGE_STREAM`: `outbound`
- `POSTMARK_SERVER_TOKEN`: copy from the Postmark production server.

## Step 5: Send a Real Test Email

Use the client auth-code flow or digest send endpoint after secrets are set.

Check:

- The email arrives in Gmail.
- The email arrives in Outlook or Microsoft 365.
- The sender shows as Daemion.
- Postmark activity shows the message as delivered.
- Postmark authentication status shows SPF and DKIM passing.

## Step 6: Tighten DMARC Later

Start with `p=none` so the team can monitor without blocking email.

After real emails pass consistently, change DMARC gradually:

1. `p=none` for monitoring.
2. `p=quarantine` when SPF/DKIM pass reliably.
3. `p=reject` only after the team is confident no legitimate mail source is missing.

Do not move to `p=reject` before all real sending sources are known.
